# 分阶段开发与验收计划

状态（2026-10-04）：8阶段划分已确认，第1阶段任务1至5已完成并提交；任务6手机基础与Android开发构建/模拟器验证通过，iOS未验收；任务7双工具链CI待开发，阶段尚未整体验收。阶段2至8未开始。当前统一执行[第1阶段实施计划](2026-10-03-stage-1-engineering-foundation.md)。

## 目标与依据

第一版面向日本的中国用户，同时开发iOS与Android，保留兴趣交友、恋爱配对、同城活动、游客图文留言板、群聊、普通私聊与管理后台。阶段划分安排开发顺序，不删减已确认模块。

依据：[产品方案](../specs/2026-10-03-social-app-design.md)、[页面与交互](../specs/2026-10-03-social-app-ui-interaction-design.md)、[数据库与API详细设计](../specs/2026-10-03-social-app-database-api-design.md)、[OpenAPI合同](../../../packages/contracts/openapi.json)。开发前统一早期技术稿中的旧规则，以最新用户确认、详细设计和合同为准；冲突先记录并解决。

手机端/后台沿用React Native/Expo/TypeScript及React；后端Java/Spring Boot、Maven、MyBatis，PostgreSQL、Redis、私有对象存储及独立worker保留。Flyway为迁移工程默认，实时协议建议Spring WebSocket＋JSON、待确认。继续模块化单体和完整用户流程交付。

## 八阶段路线与验收

### 1. 工程基础

具体任务、文件、测试命令和验收清单见[第1阶段实施计划](2026-10-03-stage-1-engineering-foundation.md)。

- [ ] 交付：手机端、API、后台与worker骨架；可复现开发环境、配置说明、日志和自动检查。
- [ ] 验收：iOS与Android开发构建可运行；API连接隔离测试数据库；迁移可重复执行；自动检查能识别失败；日志不泄漏秘密。

### 2. 身份与普通资料

- [ ] 交付：游客凭证、邮箱注册登录、令牌刷新、游客内容接续、普通资料和个人设置。
- [ ] 验收：游客可浏览；凭证只管理本人内容；验证码单次消费；刷新重放被拒绝；接续失败不影响登录、不认领他人内容；公开资料不泄漏邮箱。

### 3. 留言板与图片审核

- [ ] 交付：帖子、图文回复、图片上传、地区兴趣筛选、最小审核后台与举报。
- [ ] 验收：“游客上传→提交→审核→公开展示→本人删除”流程通过；文字和图片限制有效；待审内容不公开；越权修改被拒绝；审核与界面状态一致。公开发布前接入到期过滤与清理基础能力。

### 4. 群聊与普通私聊

- [ ] 交付：注册用户建群、直接加入、成员管理、自愿群主转让、消息、未读、断线补取、只读解散。
- [ ] 验收：无加入审批；普通私聊无需年龄声明或匹配；重复发送只保存一次；退出后读取区间和发送权限正确；拉黑及陌生联系限额有效；解散后原成员按原范围只读。

### 5. 同城活动

- [ ] 交付：注册用户发布、编辑、报名、取消、提前结束、活动群与变更通知。
- [ ] 验收：并发争抢最后名额不超卖；报名与群资格同事务变更；重要修改需确认并通知具体变更；集合信息仅授权人员可读；开始前取消释放名额、开始后退出不释放名额，两者均撤销参加者群资格。

### 6. 恋爱配对

- [ ] 交付：主动18岁声明、独立恋爱资料、开启关闭、候选、喜欢、匹配与恋爱聊天。
- [ ] 验收：未声明不能使用受控恋爱功能，普通功能仍可用；声明不标为证件核验；恋爱资料不泄漏至公开接口或图片缓存；撤销声明或匹配后禁止相关通信；展示需有效声明与合格资料。

### 7. 运营与数据生命周期

- [ ] 交付：完善管理角色、审计、任务重试、账号注销、一年到期清理、推送及运维说明；整合阶段3至6随模块实现的清理能力。
- [ ] 验收：管理身份与角色隔离；重试不重复处理；原始公开/发送时间起一个UTC日历年后正文、附件及缓存清除，闰日钳位，编辑不续期；活跃账号不因一年规则自动删除；两端真机推送验证通过。

### 8. 全链路验收与发布准备

- [ ] 交付：两端真机回归、弱网与恢复、性能验证、备份恢复、部署回滚、小范围试用及发布清单。
- [ ] 验收：核心流程全部通过；无阻断发布缺陷；恢复与回滚演练成功；测试前明确并记录性能阈值、设备范围与试用规模；商店、隐私及运营发布准备完成。

## 每个小任务的完成门槛

1. 明确接口、页面和正常/异常/权限用例；代码任务先写失败测试，再实现最小功能。
2. 新增或修改代码就近加入中文注释，解释业务、权限、事务和边界；测试用中文说明场景与预期。
3. 当步执行对应单元测试及必要的真实数据库集成测试；页面实际渲染并操作；消息、报名等关键竞争执行并发测试。
4. 失败先修复再重测；必要测试无法执行时记录制约，不标为已验收。阶段验收完整用户流程，不只检查接口状态码。
5. 记录命令、环境、结果及未实施项；差分审查和测试通过后，每一组完整变更保存一次本地Git提交。无变更不空提交，未要求不推送。
