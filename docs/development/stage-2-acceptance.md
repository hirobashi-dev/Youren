## 合同与数据库对照发现

| 要求 | V1现状 | 下一步 |
|---|---|---|
| 条款接受记录 | 已有consent_records及版本/时间字段 | 新增Mapper，与账号创建同事务 |
| 验证码消费 | email_challenges已有HMAC、attempts、expires_at、consumed_at | PostgreSQL作为权威状态，行锁串行消费；Redis负责原子发送限流 |
| 刷新轮换 | sessions已有refresh_hash、family_id、replaced_by_id、expires_at、revoked_at | 保留旧令牌摘要识别重放，锁账号后锁会话，撤销同族 |
| 游客凭证到期 | guest_credentials缺少expires_at | 新增V2字段及约束，验证V1升级 |
| 不透明访问令牌 | sessions缺少独立访问摘要及到期时间 | 新增V2，访问摘要与刷新摘要分开保存，退出即时失效 |
| 普通资料首次创建 | 合同If-Match只接受正版本，尚无资料时无法创建 | 首次允许双引号0，之后按当前正版本更新 |

实施决定：使用高熵不透明访问令牌，服务器只存摘要，每次查验会话与账号状态；普通用户和管理端凭证隔离。验证码HMAC密钥由环境注入，不使用六位验证码的无密钥摘要。外部邮件在数据库持锁事务外发送，发送失败的挑战不得消费。Redis故障拒绝发送，不绕过限流；客户端不能控制IP身份，默认不信任转发头。

已注册邮箱以有效注册挑战再次注册时返回200登录结果，不覆盖账号资料，不新增虚假条款记录；未注册邮箱用登录挑战完成登录时返回统一认证失败，不自动注册。发送验证码端点响应统一，验证码完成前不公开账号存在性。

临时网络错误保留SecureStore凭证，但不授权受保护操作；刷新请求串行，响应丢失不得盲目重放旧令牌，先按已记录状态提示重新认证。服务端明确失效或用户主动退出时清除凭证。具体行为由任务3和5测试验证。
